# 💺 AsyncTicket 좌석 Jinja2 개인 프리뷰

기존 좌석 API를 화면에 연결하며 Jinja2와 백엔드의 동작을 공부하는 개인 프로젝트입니다.

## 🎯 목표

- Jinja2로 서버에서 HTML을 만드는 과정 이해하기
- 회차별 좌석 목록·상태·가격 표시하기
- 좌석 상세 조회 연결하기
- 로딩·빈 결과·오류 상황을 화면으로 표현하기

## 🌿 시작 기준

- 원본: A팀 AsyncTicket
- 기준 브랜치: `seat-1106`
- 기준 커밋: `993e404`
- 좌석 코드는 `src/asyncticket/seats`로 통합되어 있습니다.

> 기준 커밋 이후 작성한 PostgreSQL 테스트와 검사 문서는 미커밋 상태였습니다.
> 별도 복사 여부를 확인해야 합니다.

## 🚧 작업 범위

별도 개인 프리뷰 앱과 템플릿을 만들어 기존 좌석 기능을 연결합니다.

- 공통 코드와 다른 담당 도메인은 수정하지 않습니다.
- 기존 좌석 API의 계약을 임의로 변경하지 않습니다.
- 결제·예매 확정·취소 흐름은 이번 화면 구현 범위에 포함하지 않습니다.
- `reservation_items`는 삭제 대상이며 사용하거나 연결하지 않습니다.
- 인증을 대체하거나 예시 데이터를 사용하면 화면과 문서에 명시합니다.

## 🖥️ 구현할 화면

| 화면 | 표시할 내용 |
| --- | --- |
| 회차 입력·선택 | 조회할 회차 |
| 좌석 목록 | 좌석명, 등급, 상태, 가격 |
| 좌석 상세 | 선택한 좌석의 정보 |
| 결과 안내 | 좌석 없음, 잘못된 요청, 조회 실패 |

현재 API는 좌석의 행·열·좌표를 제공하지 않습니다.
실제 공연장 배치도는 별도 배치 정보가 필요하므로 우선 목록 형태로 구성합니다.

## 🔗 사용할 API

| 요청 | 용도 |
| --- | --- |
| `GET /v1/performances/{perf_id}/seats` | 회차별 좌석 목록 |
| `GET /v1/performances/{perf_id}/seats/{seat_seq}` | 좌석 상세 |
| `GET /v1/performances/{perf_id}/seat-infos/{seat_id}` | 좌석 등급 상세 |

슬래시가 포함된 좌석명도 상세 조회할 수 있습니다.
URL에 넣는 좌석명은 인코딩해서 전달합니다.

## 🧩 화면 연결 구조

브라우저 요청 → 개인 프리뷰 앱 → 기존 좌석 기능 → 조회 결과 → Jinja2 HTML 응답

Jinja2는 조회 결과를 HTML에 표시하는 역할을 합니다.
좌석 연결 조건과 가격 검증 등의 업무 규칙은 기존 좌석 코드에 둡니다.

## 🐳 개인 개발 DB

- 컨테이너: `asyncticket-seat-local-1106`
- 접속 주소: `127.0.0.1:5435`
- DB 이름: `asyncticket_seat_local`
- 접속 정보: 개인 `.env`에서 관리

비밀번호와 JWT 키는 Git에 올리지 않습니다.

> 초기 DB의 `public` 스키마는 빈 상태입니다.
> 테스트용 임시 스키마는 검사 후 삭제되므로 화면에 사용할 데이터는 별도로 준비해야 합니다.

## 🛠️ 실행 준비

아직 개인 프리뷰 앱과 실행 진입점은 구현 전입니다.

1. 개인 DB 실행 상태 확인
2. `.env`의 접속 대상 확인
3. 개인 프리뷰 앱·템플릿 준비
4. 프리뷰용 테이블·데이터 준비
5. Jinja2를 포함해 실행
6. 실제 확인한 실행 명령을 이 문서에 추가

Jinja2는 팀 의존성 파일을 바꾸지 않고
`uv run --with jinja2` 방식으로 개인 실행에 추가할 수 있습니다.

## 🤝 좌석과 예매의 책임

- 결제 서비스: 결제 결과 판단
- 예매 서비스: 예매 상태 결정과 최종 commit
- 좌석 서비스: 전달값으로 연결 조건 검사와 기록

좌석 화면이 표시된다고 결제·예매까지 완성된 것은 아닙니다.
검증 결과는 화면, 좌석 API, 전체 예매 흐름으로 나누어 기록합니다.
